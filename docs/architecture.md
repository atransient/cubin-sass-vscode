# Architecture and migration scope

The repository root is the VS Code extension root. An installed VSIX contains the same runtime tree:

```text
package.json             Extension manifest, settings and development commands
extension.js             Custom editors, buffer history, source sync and commands
backend.js               Bounded JSON backend jobs, timeout and process cancellation
scriptpath.js            Backend discovery inside the extension installation
nvsassfs.js              In-memory source documents
basehash.js              Source/base identity shared with the backend
basehistory.js           History used for source/binary synchronization
media/                   Webview scripts, styles and bit operations
syntaxes/                TextMate grammar for .nvsass
scripts/cubin_sass.py     JSON CLI used by the extension
nvisa/model/              Encoding, parsing, assembly, fatbin and ELF rewrite logic
nvisa/oracle/             ELF bytes, nvdisasm cache and optional driver-load helpers
nvisa/analyze/fields.py   Shared encoding field primitives
nvisa/collect/harvest.py  Small CUDA seed compilation helper
corpus/cubins/            Bundled template pool and test fixtures
corpus/seeds/             CUDA source for the template fixtures
data/                    sm_90 runtime data snapshots and provenance manifest
test/                    JavaScript and Webview tests
tests/                   Python backend and standalone CLI tests
```

The extension invokes the bundled `scripts/cubin_sass.py` with the configured Python
interpreter and consumes JSON. Unsaved cubin bytes are passed over stdin. The script
locates its `nvisa` package and `data` relative to itself, so neither a specific working
directory nor the original nv_isa checkout is required.

The original package name, command IDs, configuration keys and custom-editor IDs are
preserved. The original nested `tools/vscode-cubin-sass` layout is flattened into the
root. Runtime JSON files move from `out/` into `data/`. Explicit custom backend settings
remain supported, while the default resolves inside the installed extension first.
A personal Conda interpreter fallback is removed; `cubinSass.pythonPath` is authoritative.

The backend keeps the `nvisa` namespace to avoid unnecessary ISA implementation changes.
Only its transitive runtime dependencies and ELF inspection support are copied. The GPU
performance model, experiment scripts, production-library corpora, historical scan results
and original Git history are excluded. The original repository remains unchanged.

Bundled data comprises `segtable-sm90.json`, `fieldscan-sm90.json`, `modes-sm90.json`
and `form-grammar-sm90.json`. These preserve the existing instruction knowledge;
they are not regenerated by the extension. The form grammar's local source filename is
normalized, while its original source checksum is retained. See `data/manifest.json`
for source and destination data checksums. Historical note numbers in implementation
comments refer to the original nv_isa research notes.

CUDA binaries and libraries are external dependencies, not bundled artifacts. Optional
C helper binaries are compiled into `$XDG_CACHE_HOME/cubin-sass-vscode/bin` (falling back
to `~/.cache`). The CUDA SDK is discovered through `CUDA_HOME`, `CUDA_PATH`, or `nvcc`.
The disassembler and template caches use the existing XDG-aware cache locations.

Source saves validate assembly and ELF layout before replacing bytes. Host executable
writes additionally require the embedded cubin size to remain unchanged. Driver-load
checks report missing tools or devices as skipped and never launch an edited kernel.

Virtual source saves await assembly inside the filesystem provider, so a failed assembly
leaves the source dirty and eligible for VS Code backup. Binary saves validate a fixed
snapshot; asynchronous results are applied only if the binary and source revisions still
match. Each backend transaction has a private temporary directory. Custom-editor backups
are loaded through the backup URI when VS Code restores an unsaved document.
Binary saves recheck the disk baseline after validation. Save As captures the
destination before validation and checks it again before writing. Missing-original
backup recovery keeps a distinct missing-disk state, validates all executable
instructions on save, and refuses to replace an externally recreated file.

The backend runner defaults to two active jobs and at most 32 queued jobs. Its
120-second timeout includes queue time. Concurrency and timeout are configurable;
queue capacity is fixed. Preview
generations replace older jobs with the same key. Document edits and closure,
save cancellation tokens, the cancel command and extension disposal stop affected
work. Linux jobs run in separate process groups: cancellation sends TERM, followed
by KILL when needed, including descendants. Infrastructure failures cannot be
bypassed using experimental save. Assembly template text is indexed by section
and address so kernels with overlapping addresses keep their own encodings; old
flat-address template caches are invalidated.

Embedded-image source URIs include the selected image index as well as the base path
and section. This keeps source documents distinct even when images have identical
kernel names or payload hashes. Rehydration, source-only saves and live-buffer assembly
all use that binding. Undo restores only the bound image payload inside the current host
snapshot, preserving edits to other images and the preview's current image selection.

CLI source saves with `--stdin` use the supplied bytes as the base even when `--out` is
given. They retain full save verification and atomic output replacement; the positional
path need not exist. Without `--stdin`, disk-based source saves keep their external-change
checks. CI runs both a toolchain-independent job and a CUDA 12.9.1 container job with the
full slow Python suite and mandatory real-backend JavaScript integration tests.
